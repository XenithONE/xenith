## 3. 一致：草案3「権能を取らない＝純粋」は**証明可能に偽**（3/4）

codex と opencode が**独立に同じ反例**を出した。議論の余地がない。

```
fn save_callback(fs: Fs) {
    callbacks.add(fn() { fs.read(...) })   // クロージャが fs を捕獲
}

fn run_callback(callback: fn() -> Unit) {  // 権能を取らない = 私の定義では「純粋」
    callback()                              // 実際にはファイルIOを行う
}
```

権能は**クロージャに捕獲され、オブジェクトに格納され、インタフェース越しに渡る**。
コンストラクタを private にしても何も変わらない。
私の規則は「呼び出し側が真実を最も必要とする場所で、不純なコードを純粋と表示する」（opencode）。

### 決定（採択する修正）
権能は値のまま残す。加えて **閉じた効果集合を関数**型に載せる：

```
fn load_config(fs: Fs) -> Result<Config, Error> uses {Fs.read}

// 高階関数のために効果集合変数を1つだけ導入する（行多相もHKTも入れない）
fn map<T, U, E>(items: List<T>, f: fn(T) -> U uses E) -> List<U> uses E
```

- 公開シグネチャは効果を**宣言**、ローカル関数は**推論**、コンパイラが照合。
- クロージャは捕獲した効果を持ち回る。関数値は効果要約を持つ。FFI は常に有効果。
- 「効果多相を入れない」は妥当。だが「**効果検査を入れない**」は妥当でない（opencode）。

### 却下：agy の「暗黙の権能節（auto-threading）」
agy は「配管感染（plumbing infection）」と引数順ハルシネーションを理由に、
`using [...]` で権能をコンパイラが自動で下位に流すことを提案した。
**却下する。** 呼び出し側のシグネチャが嘘をつくようになり、原則1（局所完結性）を破壊する。
LLMは「この関数が何にアクセスできるか」を呼び出し地点で読めなくなる。
ただし配管の苦痛という指摘自体は正しいので、**権能バンドル**（`Sys` を1つ渡して絞り込む）で緩和する。

## 5. 争点：文の終端（2対1、事前登録も懸念側）

- **grok**: 「改行ASIを落とせ。**波括弧の方が転移が良く**、Goの `return\nfoo` クラスのバグを消せる。」
- 事前登録: 私も「4番が最も危うい」と書いていた（同じ `return\nfoo` を理由に）。
- **agy**: 維持でよい（ただし行末演算子の扱いを明確にせよ）。
- 観察: **4モデルの構文サンプルは全部セミコロン無しの改行区切りだった。** 実物では誰もセミコロンを書かない。

### 決定（折衷・採択）
セミコロン無しの改行区切りを**維持**する。ただし `return\nfoo` クラスを**文法から消す**：

- **`return` は常にオペランドを要求する**（値が無い場合は `return unit`）。
- `break` / `continue` はオペランドを取らない。
- 継続は未閉じの `(` `[` の内側でのみ。

これで「改行の有無で意味が変わる」構文上の位置が消える。Goの罠は `return` の
オペランドが**省略可能**だったことに由来しており、必須化すれば原因ごと無くなる。

## 6. 争点：メモリモデル（1対1、技術的にgrokが正しい）

- **grok**: 「ARC + アリーナはゲームと戦う。**循環参照/Weak・clone多発・参照カウントのホットパス末尾**。
  借用チェッカ非採用は維持しつつ、既定は**アフィン所有権 + 明示的な `share`/`clone`**、
  ARCは**型コンストラクタの裏に置く**（暗黙の既定にしない）。」
- **agy**: 草案2は「正しい」と評価。

### 決定
grok を採る。**可変値意味論（mutable value semantics, Hylo/Val系）**を基礎に据える：
- 既定は**ムーブ（アフィン）**。ライフタイム注釈はユーザーコードに一切登場しない。
- 共有が要るときだけ明示的に `Shared<T>`（ARC）。**暗黙のARCは無し。**
- ホットパス用に明示アリーナ。

借用チェッカを持たないという核心は変わらない。**ARCを暗黙の既定にしない**点だけを変える。

## 7. 一致：C ABI は必要だが不十分（4/4）

4モデルとも「生のC ABIを言語向け拡張モデルにするな」で一致。

- **codex / opencode**（ほぼ同一の提案）: **小さくバージョン付きのIDL**を定義する。
  レコード・バリアント・リスト・文字列・不透明ハンドル・コールバック・`Result` のみ。
  境界ごとに `borrow` / `take` / `copy` の所有権を明示。確保の所有者は片側のみ、境界越えの解放を禁止。
  ARCオブジェクト・巻き戻し・native asyncフレーム・アロケータ依存文字列を**Cに露出させない**。
  ネイティブC ABIへ下ろす（ゲーム）＋ WASM Components は後日の追加バックエンド（サンドボックス/サーバ）。
- **grok**: **凍結した、ツール生成のバインディングIR**（成果物をコミットし、利用者側に libclang を要求しない）。
  加えて `std/game` と `std/server` の**2プロファイル**に分ける。
- **agy**: Zig 流の `@cImport`（Cヘッダ直接取り込み）で40年分のC資産を継承。
- 事前一致: 私の D（「バインディング自動生成まで含めて初めて戦略」）と一致。

### 決定
**消費側**（既存C資産を使う）= agy の `@cImport` 相当のヘッダ取り込み ＋ grok の凍結生成物方式。
**露出側**（Xenithを他言語から使う）= codex/opencode の小さなIDL。
WASM Component Model は**追加**バックエンドであって唯一の境界にはしない（ゲームのフレーム予算を殺すため）。

## 10. 改訂後の評価指標

ベンチマークを3条件の**比較**に変更する（単一条件の pass@1 をやめる）:

1. `full-pack` — 実務手引き全部を文脈に入れる
2. `retrieved` — タスク関連の型・シグネチャ・検証済み具体例だけを取得して入れる
3. `hole-guided` — コンパイラのホール／クエリを使いながら構築する

指標は各条件の **pass@1** と **緑になるまでの平均修正回数**。
仮説「3 > 2 > 1」が成り立つかを測る。成り立たなければ本文書の方針転換自体が誤りであり、その時点で再検討する。

> 実行は従量課金APIを使わず、サブスク済みCLI（`codex` / `grok` / `agy` / `opencode`）にシェルアウトする。
> したがってCIには載らず、ローカル手動実行＋結果コミット運用とする。
