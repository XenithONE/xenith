# 0016 — 測定 RFC: タスク構造の適性（使用監査つき）

- 日付: 2026-08-08
- 状態: **採択（4モデル並列レビュー後の全面改稿）**
- 手法: 事前登録 → codex / agy / opencode / cursor(grok-4.6-xhigh) の攻撃 → 統合。
  **4/4 が同一の Q5 を突いた**: 隠しテストが stdout 一致である以上、fan-out は逐次解でも
  緑になる。**「緑 = タスク構造の適性」ではない。** 走数配分（3 / 28 / 224）も
  4/4 が倒錯と判定。本 RFC はその2点を軸に作り直した

## 0. 中核の是正 — 緑を二層にする（4/4 の最危険への回答）

0012 は「効果の帰属を**配達実績**で縛る」を確立した。0016 はその双子を追加する:
**構文の帰属を使用実績で縛る**。

- 提出プログラムから機械的に記録する**使用監査**: `scope` / `spawn` / `.await` の出現、
  子の `uses` が空か、Join の await 回数、CaptureSafe 引数か
- 結果を**3クラスに分離**（opencode の分類を採択）:
  **(A) 迂回して緑**（タスク構文なしで stdout 一致）/ **(B) 使用したが不正**（構文は出たが
  診断 or 出力不一致）/ **(C) 使用かつ緑**
- **t7 の pass@1 は (C) のみを分子にする**。(A) は別欄で報告する（それ自体が
  「タスクは事前分布に無い」という結果だが、適性の数字ではない）
- 課題設計でも迂回を減らす: **子は値を返し、親が await して集約してから一度だけ出力する**
  （agy 代案）。stdout は決定的（0015 は即時完走なので順序は元より決定的）

## 1. P1 課題 — 手順0は測定層と同じ母集団で（4/4）

- **手順0（探索・凍結の入力）: 7モデル × 3課題 = 21走**。1モデル3走の分布を7モデルの
  罠に固定するのは「特定1モデルの3件への過学習」であり null の再発（agy/cursor）
- 手順0の課題文は**凍結課題と同型の fan-out** にする（「タスクを使え」という自由記述は
  分布が違う — cursor）
- **t7-02 は手順0の結果で消さない**（cursor の急所）: XN6002（子の純粋性）は捏造した
  誘惑ではなく **0015 が出荷した固有拘束そのもの**。観測ゼロで差し替えるのは
  「罠を捏造するな」ではなく「固有拘束を測るな」になる。t7-02 は
  「効果を扱う親＋子に効果を書きたくなるが `uses {}` が拒む」構図で**無条件に凍結**する
- 手順0で実際に出た診断コードごとに**構図を1本足してよい**（本数は 2〜4 本。
  捏造で本数を増やさない — cursor の「実測から作る」本則）
- 参照解は spawn/await を使い、verify は 26〜28 参照解へ

## 2. P2 再較正 — H3 は削除、基線更新に縮小（4/4）

- 草案の「旧課題16本×2腕=224走」は**識別不能**だった: 比較対象 v3 は旧ガイド・旧モデル版数
  （grok 4.5）の歴史値であり、g3 との差は「増量」「版数」「時間」の交絡（4/4）
- **H3 を仮説から削除**。増量の因果を測るなら「現行ガイド vs Tasks/クロージャ節を抜いた
  ガイド」を同一版数で同時に打つ必要があり、それは測定中のガイド凍結と衝突する
  （cursor）。増量の効果は **t7 で測れる**（Tasks 節が効く面はそこだけ）
- 基線更新が要るなら**代表4課題 × 7モデル × 2腕 = 56走**に縮小し、
  「現行ガイド有無が旧課題を動かすか（g3-docs vs g3-plain）」だけを読む。
  歴史値との同値主張はしない。**版数が変わったモデルは比較から外す**（注記で逃げない）

## 3. P3 走数配分（倒錯の是正）

| 実験 | 走数 | 目的 |
| --- | --- | --- |
| 手順0（7モデル×3課題） | 21 | 凍結の入力・分布の実測 |
| tier-7（2〜4課題×7×2腕） | 28〜56 | **本 RFC の主目的** |

## 4. P4 仮説（両勝の封鎖・配達を前置）

- **H-使用（新設・0014 型）**: t7 で提出の過半が `spawn`/`await` を含む。
  含まなければ「タスク構文は事前分布に届いていない」— これは適性の測定ではなく
  **到達の測定**であり、そこで RFC は結論を分岐する
- **H-配達（新設・H2 の前提）**: t7 の失敗ラウンドで XN6xxx が feedback に載る。
  **手順0で v3 クローン腕が XN6xxx を実際に配達することを先に確認**してから
  t7-teach を凍結する（0012 の再演を防ぐ）
- **H1（改訂）**: (C) 使用かつ緑の p@1 は、**同一モデル集合・現行ガイド**での t6-01 相当面
  より低い。逐次緑は分子に入れない。高く出た場合は「綴り成功」と即断せず、
  **(A) 迂回率**と**検証が spawn を要求しているか**を先に切り分ける（両勝の封鎖）
- **H2（改訂）**: 配達された部分集合でのみ rounds-to-green を読む。不配達なら
  **「H2 は未検定」と書く**（自動成立の逃げを削除）
- **H-交差**: Tasks 節は t7 で効き、旧課題では効かない（H3 の代替・識別可能な形）
- 反証は方向つき: t7 で不使用のまま緑が支配 → **verify が北極星指標になっていない**
  （課題設計の欠陥として 0017）/ XN6xxx 不配達 → 診断は出荷したが拘束回路が届いていない /
  旧課題で docs が下がる → 増量有害を 0017 へ

## 5. P5 入れないもの

- 新条件の発明（既存腕のクローンのみ）・凍結後の課題改変（再凍結して記録）
- ガイドの変更（測定中は凍結）・歴史値との pass@1 同値主張
- 想像から作った罠（手順0で観測された誤りのみを構図に織り込む）

## 6. 却下された草案要素（記録）

- **stdout 緑をそのまま p@1 にする** — 逐次迂回を「タスク適性」と読む致命的誤り（4/4）
- **手順0 = 1モデル×3走** — 測定層と母集団が違う。過小標本の無発火を言語特性に読み替える危険
- **再較正 224走（88%）** — 識別不能な交絡に予算の大半。主目的が付録になっていた
- **t7-02 を手順0の結果で差し替え** — 出荷済みの固有拘束を測らない選択になる
- **H2「発火すれば効く」** — 不発火時に自動成立する。配達率の予測を前に置く
