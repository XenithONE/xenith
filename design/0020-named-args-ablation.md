# 0020 — 言語結合部のアブレーション: named args（採択版 — 大半は「走らせない」）

- 日付: 2026-08-16
- 状態: **採択（4モデル並列レビュー後の全面改稿）**
- 手法: 事前登録（0c6e1d6）→ codex / agy / opencode / cursor(grok-4.6-xhigh) の攻撃 → 統合。
  **4/4 が E1・E2 の両方を棄却。** 私の事前登録は3箇所で負けた:
  H-静音の連言（full=0）が偽・発火ゼロ無効化条項が逆向き（mediator 選別）・
  E2 が自 RFC の「後付け不能」定義に自ら違反

## 0. レビューが走行ゼロで確定させた事実（本 RFC の主成果）

1. **named args の実保証は草案の読みより狭い**: XN3008 が殺すのはラベル欠落、
   XN3003 が殺すのは宣言順違反。**「役割ラベルへの値の付け違え」
   （`transfer(from: beta, to: alpha, ...)` — 名前も順も正しく値だけ逆）という
   静音クラスは残る**（4/4）。「full 腕は構造的に 0」は偽 — stdout を判定に使えば
   誤分類、構文交換だけをバグと定義すれば恒真の循環（codex）
2. **stdout 指紋は帰属にならない**: 証明できるのは「順序バグ ⇒ この stdout」で
   あり逆ではない。帰属には AST か callee 入口の引数トレースが要る
3. **機械 fix は洗浄しうる**: 位置呼びへ宣言順で名前を付ける fix は、誤った束縛を
   保存したまま診断だけを消す（opencode）— fix の設計自体への宿題
4. **uptake は保証されない**: API 表が名前と宣言順を運ぶ限り ablated 腕にも完全な
   回復経路があり、ablated 検査器は named 呼びを受理するので、モデルは普通に
   named を書いて実験が空転する
5. **発火ゼロ＝無効の条項は逆向き**: 規則の予防効果は「発火ゼロ」として現れる。
   mediator で結果を選別する条項だった
6. **「後付け不能」は定義で勝っているだけ**: opt-in strict mode・lint・codemod は
   新規コードに規則を課せる。主張の上限は「エコシステム既定としての強制」に下げる

## 1. 採択する測定

### C1 — 構造試験（LLM 不要・conformance で証明できる）

「同型引数の位置交換は、ablated では型を通って実行され黙って誤答し、full では
XN3008/XN3003 になる」— この**階級転換そのもの**は決定的な事実であり、
モデル実験を要しない（codex 代案1）:

- checker フラグ `--ablate=named-args`（XN3008/XN3003 抑制・宣言順で位置束縛。
  測定専用・spec 不変・フラグ無しはバイト不変をテスト断言）
- conformance: 交換済み client を両検査器へ交差投入。full = 診断、
  ablated = 実行成功＋**callee 入口の引数トレース**が交換を示す
- **実装は #29（check.rs 分割）のブランチ合流後**（同一ファイルへの競合回避）

### C2 — 発生率測定（登録のみ・今は走らせない）

モデルが実際にどの頻度で位置交換を書くかは、codex 代案2の形でのみ識別可能:
**arm-blind 単回生成**（statement 正順/逆順を無作為化）→ **同一バイト列を両検査器へ**
→ AST／引数トレースで分類（stdout 不使用）。プロンプト非対称も uptake 問題も消える。

ただし**今は起動しない**: 発生率の絶対値は課題文の作為に敏感で、外的妥当性を
主張するには #31 の課題拡充が先。C1 が構造を証明した後、0004 再審議や対外主張が
実数を必要とした時のみ、この設計で走らせる。

## 2. 削除されたもの

- **E1（執筆実験・指紋帰属）** — §0-1〜4 により識別不能。逆順 statement は
  自然言語の読み違えを full 腕にも誘発し、規則ではなく読解を測る（agy）
- **E2（teach 名前アブレーション）** — 診断文字列への名前追加は tsc にも自明に
  後付け可能で、「後付け不能な結合部」の挙証にならない（agy/opencode）。
  名前は API 表・誤記した識別子自身・機械 fix からも漏れ、レンダラだけでは
  隔離できない。「親切な診断の効果測定」としてなら別 RFC で設計し直す
- 局所推論・効果検査・fmt のアブレーション（草案 §6 のまま — 不可能・二重強制・
  ループ不在）

## 3. 帰結 — 「新言語が必要か」の現在の正直な答え

- 0019: teaches **機構は可搬**（19対0）
- 0020: named args の**構造保証は実在するが狭い**（ラベル欠落と宣言順violation の
  除去まで。値の付け違えは残る）。保証の実在は C1 の conformance で証明できるが、
  **その実利の大きさを人工課題で言うことは現在の計器では識別不能**
- したがって表看板は「新言語だから優れている」ではなく引き続き
  「コンパイラを対話相手にする機構の実測」に置く。言語固有価値の定量は、
  C2 級の設計と #31 の課題母集団が揃うまで主張しない

## 4. 却下された草案要素（記録）

- full=0 の構造主張（4/4: 役割誤束縛が残る）・stdout 指紋帰属（4/4）・
  逆順 statement による罠設計（agy: 読解交絡）・teach 名前切り出し（4/4）・
  発火ゼロ無効化条項（opencode: mediator 選別）・「≥2 / 0」の恣意的閾値（codex）
