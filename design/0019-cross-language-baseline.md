# 0019 — 測定 RFC: 言語横断基線（teaches-for-TypeScript）

- 日付: 2026-08-13
- 状態: **草案（事前登録 — 4AI 攻撃レビュー前）**。本文は私（Claude）の事前登録であり、
  レビュー後に全面改稿されうる。予測は §5 に固定済み
- 動機: GPT 外部評価の最重要指摘 —「Xenith が優れているのか、Xenith のツール群が
  優れているだけか。Rust/TS に同等 protocol を付けた基線が無い以上、『AI のために
  新しい言語を作る価値がある』は未証明」。同じ実験には Autoscript 5AI 諮問
  （Phase A: teaches-for-TypeScript）が独立に到達済み。現在の全実測は Xenith 内の
  腕比較であり、証明済みは「コンパイラを agent の対話相手にすると効く」まで

## 1. 問い（1つだけ）

0009 の teaches 効果（文書ゼロ文脈で修復 34/42 → 40/42）は**言語固有か、可搬か**。

測定量は**差分の差分**である: TypeScript での teaches on/off の Δ（失敗ラウンドの
修復成功率）を、Xenith の Δ と比較する。**絶対 pass@1 の言語間比較はしない** —
事前分布・課題・標準ライブラリが交絡し、どの向きの差が出ても識別不能だから。

## 2. 装置 — ts-teaches（bench/baseline/ts-teaches/）

- Node + 依存は `typescript` 1本のみ。版を厳密固定・`--ignore-scripts`・lockfile
  コミット（ChainDrop 事後の最小 npm 表面。導入直後に再スキャナを1回かける）
- tsc API（Program + TypeChecker）のラッパ CLI。`--teaching=off` で素の tsc 診断と
  **バイト同一**（0009 と同じ自己検証テスト）
- teaches 対象の診断族は**手順0の実測から確定**する（想像で罠を作らない — 0016 の規律）。
  候補見込み: TS2339（未知プロパティ）/ TS2345（引数型）/ TS2554（引数個数）/
  TS2551・TS2552（名前近似）
- 添付内容は 0009 と同型: 誤り地点に関係する**正確なシグネチャ／メンバー表**を
  構造化で自発添付。件数・バイト予算・重複排除も 0009 準拠
- 修復ループは xenith-bench と**同一ハーネス**（条件分離・ラウンド上限・ナッジ対称・
  中立 cwd・空応答検出・配達監査）。ランナーは既存 Rust 側に TS バックエンドを足す

## 3. 課題設計 — 事前分布を外す

TS の既知 API（fetch / fs / Array…）では初回失敗がほぼ起きず、修復面が測れない。
よって各課題は**同梱ローカルモジュール**を使わせる:

- 課題ディレクトリに `lib/`（新規の API 表面 — 型と関数、文書なし）を同梱。
  statement は lib を使って結果を stdout に出すことを要求
- モデルは import → 呼ぶ → 誤る → 診断 → 修復の面に必ず乗る
- 6課題（0009 v3 の t 族と同規模）。参照解＋隠し stdout オラクル＋実装前凍結＋
  verify 全緑＋statement に teaches 語彙のリーク無しをテストで断言
- 手順0: 7モデル × 2課題（teaches なし）で**実際の失敗分布**を採り、
  teaches 対象コードを実測から決める

## 5. 事前登録の仮説と分岐

- **H-可搬**: ts-teach は失敗ラウンドの修復成功率を ts-plain より上げる。
  **私の予測: 成立** — 機構（誤り地点に欠けている事実を置く）は言語非依存のはず
- **H-差分**: TS の Δ は Xenith の Δ より小さい。**私の予測: 成立** — tsc の素の
  診断は既に型名・部分的なシグネチャ情報を含み床が高い。加えて Xenith 側は
  named args（引数順の誤りが構文エラー）と局所推論（葉を直しても根の型が動かない）が
  teaches の着地を良くしている疑いがある
- **分岐の意味（両方を先に書く）**:
  - **可搬（Δ_TS ≈ Δ_XN）** → teaches に言語は不要 = GPT の疑いが確定。Xenith の
    必要性の主張は**ラッパで後付け不能な言語結合部**（署名が嘘をつけない効果検査・
    名前付き引数の強制・局所推論・正典 fmt）へ移る。Autoscript Phase A は GO
  - **不可搬（Δ_TS ≪ Δ_XN）** → teaches の効きが Xenith の構造に依存する
    **初の直接証拠** = 「新言語が必要」の最後の一段への最初の足場
  - どちらでも記録に値する。この実験は「負けない」のではなく**どちらの負けかを決める**
- **H-発火**（0012 の双子）: teaches が実際に載ったラウンドを配達監査で記録。
  不発火のまま Δ が出たら計器を疑う

## 6. 入れないもの

- Rust 基線（rustc の素の診断は既に teaches 的で床が高すぎる — 別 RFC。TS を先に
  する理由: 事前分布最大・素の診断が中庸・ヘッドルーム最大）
- 絶対 pass@1 の言語間比較・「Xenith の方が良い言語」という結論の先取り
- tsserver プラグイン / LSP / MCP サーバ（測定に不要 — 製品トラックの領分）
- 新条件の発明（腕は 0009 v3 の 2腕クローン）
