# 0014 — クロージャ: 能力効果ゼロの関数値（採択版）

- 日付: 2026-08-08
- 状態: **採択（5モデル並列レビュー後の改訂版）**
- 手法: 事前登録 → codex/grok/agy/opencode/cursor 並列攻撃 → 統合。**中心命題が撃破された**:
  「捕獲できない＝純粋」は偽 — `|io: Io| io.print(x)` は何も捕獲せず能力を**引数で受けて**
  効果を起こす（codex/grok/opencode 同着）。守りは構成ではなく**二本柱**になった。
  再帰の XN3011 委任はカテゴリ錯誤（無限サイズ型ではなく未初期化自己参照）、
  Rust 形の負転移は「付随損害ではなく本体」、fold の正典欠落も撃たれた

## 1. 中核 — 二本柱の能力効果ゼロ

主張を「純粋」から**「能力効果ゼロ」**に降格する（発散・失敗は禁じない — grok）:

- **柱1 本体検査**: クロージャ本体は**暗黙の `uses {}`** で既存の効果検査器にかける。
  能力操作も、`uses` 非空の名前つき fn の呼び出しも、経路を問わず本体で拒否
  （直接・引数経由・ジェネリック経由すべて compile-fail 試験で固定）
- **柱2 捕獲制限**: 捕獲できるのは **CaptureSafe** な値のみ。CaptureSafe は帰納定義で
  RFC が固定: プリミティブ=可 / 積・和・List/Map/Option/Result=成分が全部可なら可 /
  fn 型=可 / **能力型=不可** / **同一性・共有可変・資源ハンドルを導入する型=不可**
  （0004 の共有可変プリミティブは実装前から非 CaptureSafe と**ここで予約** — 将来の穴を
  先に塞ぐ）/ 未解決型パラメータは `T: CaptureSafe` 境界がなければ不可 / opaque=不可
- fn 型は `fn(T) -> U` — 効果節なし（常に空だから書かせない）。複数引数の fn 型は
  **仮引数名を持つ**（`fn(acc: Int, x: Int) -> Int`）— 文書として（呼び出しは §3 で不能）
- 自由変数の規則3分解（grok）: (a) 値 → 生成時コピー捕獲 (b) **名前つき fn → 解決で
  あって捕獲ではない**（非空 uses なら柱1違反として別診断）(c) `var` → 捕獲前に拒否
- 診断は分離: XN4005 CapabilityCapture（非 CaptureSafe 捕獲）/ XN4006 EffectInClosure
  （本体の能力効果）/ XN4007 ClosureSelfReference（下記）。teach は全部**同じ文**に収束:
  「クロージャは計画 — 効果は囲む名前つき fn の while で実行し、クロージャはデータを返す」
  （「能力は引数で渡せ」は誤誘導なので**書かない** — opencode）

## 2. 捕獲の意味論

- **生成時点スナップショット**（意味論。実装は不変環境の共有ボックス可 — 観測上
  エイリアス無しが契約）。ネストしたクロージャは再スナップショット
- `var` 束縛の捕獲は禁止。fix は「`let` に束縛」＋**「スナップショット後の更新は
  見えない」を診断文に明記**（codex — 単なる書き換え指示にしない）
- **自己参照・前方参照・相互再帰の禁止は専用規則**（XN4007・definite-initialization）。
  XN3011 への委任は削除（型は有限 — カテゴリ錯誤だった）。再帰は名前つき fn で
- fn 値の `==` / hash / シリアライズは無し（§5 に明記 — `fns.contains(f)` は型エラー）
- 大きなコンテナの捕獲は合法（D1 と同型のコピー）。閾値は発明しない。field-guide に
  「大きな値は捕獲せず引数で渡す」を1行

## 3. 構文 — 呼び出し引数位置専用（grok 案を採択）

- **v1 のクロージャは呼び出しの引数位置にのみ書ける**。let 束縛・返り値・コンテナ格納・
  フィールドは不可（診断+fix「インライン化するか名前つき fn へ」）。これで
  「fn 値を呼ぶ」経路が消え、名前付き引数規則との衝突（位置呼びの復活）が構造的に
  起きない。0010 の「呼びの綴り1つ」も無傷
- 綴りは2形のみ: `|x| expr` / `|x| { ... }`（最後の式が値）。ゼロ引数 `||`・破棄 `_` 可。
  **ラムダ内の型注釈構文は存在しない**（引数型は期待型から局所決定 — 双方向検査の
  既存経路。正典形が1つに固定され、fmt の剥がし規則も不要 — opencode/agy）
- `?` はクロージャ本体で**禁止**（専用診断+teach「クロージャから外へ早期リターンは
  できない — 失敗を伴う反復は while へ」— agy の急所への回答）。return/break も同様
- Rust 由来の誤形（`move` / 参照捕獲 `|&x|` / `FnMut` / async クロージャ / `.iter()`）は
  パース段階の専用認識で拒否し、同じ teach に収束させる（負転移は事後策ではなく出荷物）

## 4. std — 最小4本・契約つき

- **List.map / List.filter / List.fold / List.find** のみ（any/all/sort_by/flat_map/Map.* は
  実測需要待ち — 帰属可能性を守るため最小で出す。cursor/codex の折衷）
- 契約を api-table に固定: 全て左から走査・新しいコンテナ/値を返す・find は短絡で
  `Option<T>`・**fold は左畳み込み `fold(init: B, f: fn(acc: B, x: T) -> B)`** —
  2引数呼びなので名前付き必須が既存規則から自動で効く。正典例:
  `xs.fold(init: 0, f: |acc, x| acc + x)`
- for_each は入れない（純 Unit コールバックは無意味＋効果誤解の誘発 — codex）。
  効果つき反復の正典は「while + 能力引数つき名前つき fn」で field-guide に明文化

## 5. 入れないもの

- 効果つき fn 型・効果行多相（**再開条件は 0004 の撤回であり本 RFC の延長ではない** — grok）
- 名前つき fn の値化・eta 変換・部分適用・カリー化（綴り二重化。需要実測待ち）
- let 束縛クロージャ（v1 制限。解禁するなら注釈必須 let のみを別 RFC で）
- `for` 文（while で書ける糖衣。効果反復の失敗が実測で支配的なら別 RFC — codex/opencode 案として記録）
- fn 値の等値・ハッシュ・直列化 / var・参照捕獲 / 再帰クロージャ / async・.await（維持）

## 6. 検証と測定

- **安全性は実験ではなく無条件ゲート**（codex）: compile-fail 電池 — 能力捕獲・
  引数経由の能力使用・ジェネリック洗浄・非空 uses fn の本体呼び出し・自己参照・
  var 捕獲・let 位置クロージャ・`?`・Rust 誤形。off 系の凍結はそのまま
- 表現力の測定（小走・既存条件ペア）: 課題は**純変換1本＋「途中で Io が欲しくなる」1本**
  （cursor の急所 — 純 HOF が自然な課題だけで測ると最悪の衝突を見ずに出荷する）。
  記録: XN4005/4006 率・効果課題の rounds-to-green・誤捕獲率
- 段階的判定（0012 方式）: 悪化が出たら (A) 診断/teach の配達監査 → (B) field-guide の
  計画/実行パターン正典化 → (C) それでも支配的なら `for` 文 RFC を起こす。
  「言語は変えない」を先に結論しない（codex — 反証条件の体裁を守る）

## 7. 却下された草案要素（記録）

- 「捕獲禁止＝構成的純粋」— 偽。引数経由の能力使用が素通りする（3/5 が同着で撃破）
- 再帰クロージャの XN3011 委任 — 無限サイズ型ではなく未初期化参照の問題
- `|x: Int| -> Int { ... }` 注釈形 — 正典形の分裂。注釈構文ごと廃止で解決
- 一括6+2メソッド出荷 — 失敗モードの帰属不能。最小4本＋契約に縮小
- teach「能力は引数で渡す」— 柱1違反をモデルに教える誤誘導文だった
