# 0020 — 測定 RFC: 言語結合部のアブレーション（named args）

- 日付: 2026-08-16
- 状態: **草案（事前登録 — 4AI 攻撃レビュー前）**
- 動機: 0019 の帰結。teaches 機構は tsc にそのまま移植でき同符号で効いた（19対0・
  p=3.8e-6）。ゆえに Xenith 固有の価値の挙証責任は**後付け不能な言語結合部**へ移った。
  0019 レビューで 3/4 が独立に提示した唯一の識別可能設計 —「teaches を固定し、
  言語結合部を1本ずつ落とし、どれが成績を殺すかを見る」— の第1号
- **「後付け不能」の定義（先に固定する）**: 既存エコシステムを壊さずに既存言語へ
  課せない規則。lint で新規コードに課すことは常に可能だが、既存コードの大半が違反する
  規則の強制はフォークと等価であり、「既存言語＋ラッパ」の選択肢には入らない。
  named args 必須（2引数以上）はその典型

## 1. 問い（1つだけ）

XN3008/XN3003（named args 必須＋宣言順検査＋機械 fix）は、実測で
**エラーの階級を変える**か — 同型引数の順序間違いという「静かな誤り」
（型を通り、実行され、黙って誤答する）を「大きな音の誤り」（診断＋fix）に転換し、
その転換は成績を動かすか。

XN3008 の explain 文は既にこう主張している:
「swapped positional arguments type-check and then misbehave at runtime」。
本 RFC はこの出荷済みの文が実測で真かを問う。

## 2. E1 — 執筆実験（規則はエラー級を除去するか）

- 課題: 隣接する同型引数を持つ関数群の lib（例 `transfer(from: String, to: String,
  amount: Int)`）。**API 表は両腕共通で文脈に与える**（知識は定数・規則だけが変数）。
  statement の自然語順は**宣言順と逆**に書く（「beta へ alpha から 30 を送れ」）—
  順序の罠に実際に乗る面を作る
- 腕: `full`（現行）/ `ablated`（`--ablate=named-args`: XN3008/XN3003 を抑制し
  位置引数を受理・束縛は宣言順）。モデルは statement から client を新規執筆
- **順序バグ指紋**: 参照解の同型引数を機械的に置換した変異体の stdout を事前計算。
  提出の stdout が指紋と一致すれば「順序バグ」と機械帰属する（目視判定なし）
- 判定量: 腕別の **silent-wrong-order 率**（診断ゼロ・実行成功・指紋一致）。
  full 腕では XN3003/XN3008 が捕捉するため**構造的に 0 のはず** — 0 でなければ
  検査器の穴として別途記録
- 規模: 3課題 × 7モデル × 2腕 = 42走（0019 の非対 grok を除けば実効 36）

## 3. E2 — 修復リプレイ（teach の名前成分の切り出し）

0019 の計器設計を Xenith 側へ移植し、**ペイロードの名前だけ**を落とす:

- broken client（引数個数・誤名・引数型 — 0019 と同族）を機械注入・凍結。
  単発修復・動的オラクル・配達監査 — 全て 0019 と同じ
- 腕: `teach-full`（現行: `record_entry(ledger: Ledger, label: String, amount: Int)`）
  / `teach-typesonly`（`--ablate=teach-names`: `record_entry(Ledger, String, Int)`）
- 判定: 同一 client・同一モデルのペア符号検定（0019 §3 と同じ規則）
- 規模: 3スキーマ × 3バグ族 × 7モデル × 2腕 = 126走以下

## 4. 装置

- checker フラグ `--ablate=named-args`: XN3008/XN3003 の発行を抑制し、位置引数を
  宣言順で束縛（束縛機構は check.rs の `param_names` 空経路が既に持つ）。
  **フラグ無しの出力はバイト不変**（テスト断言・0009 の規律）
- teach レンダラフラグ `--ablate=teach-names`: シグネチャの引数名を伏せ型のみ。
  同じくフラグ無しはバイト不変
- 工程は 0015 と同じ: conformance ケース（ablated で位置呼びが通る・full で
  XN3008/XN3003 が出る・両フラグの既定不変）を実装より先にコミット
- アブレーションフラグは**測定専用**として文書化（言語仕様の変更ではない —
  spec は動かさない）

## 5. 事前登録の仮説と分岐

- **H-静音**: E1 の ablated 腕で指紋一致の silent-wrong-order が発生する
  （腕合計 ≥2）。full 腕では 0。**予測: 成立** — モデルは自然語順に引きずられる
  （逆順 statement が罠に乗せる）
- **H-名前**: E2 の不一致ペアで teach-full が勝ち越す。**予測: 成立、ただし
  効果は小さい可能性** — 型だけでも位置は復元できる場合が多い（0019 の 2554 勝ちの
  何割が名前由来かの切り出しになる）
- 分岐の意味:
  - H-静音成立 → 「規則がエラー階級を構文的に除去する」の初の直接実測。
    後付け不能な言語価値の**第一号の実証**（エコシステム互換の定義により
    既存言語には課せない規則）
  - H-静音不成立（ablated でも順序バグが出ない）→ モデルの事前分布が既に
    順序を守る = named args の防御は現行モデルには冗長 → **0004 の
    名前付き引数規則の再審議を登録する**（負担だけが残るなら規則を疑う —
    設計を守るために結果を曲げない）
  - H-名前は方向どちらでも 0019 の勝因の分解として記録に値する
- **H-発火**（継承）: E2 の teach 配達を機械記録。E1 の full 腕では
  XN3003/XN3008 の発火率を記録（発火ゼロなら罠に誰も乗っていない = 課題設計の失敗
  として E1 を無効と宣言する — 両勝の封鎖）

## 6. 入れないもの

- **局所推論のアブレーション** — 「全プログラム推論の Xenith」は別コンパイラの
  実装であり不可能。この柱は**未検証と正直に記録**する（比較不能を比較可能と
  偽装しない）
- **効果検査のアブレーション** — 能力は値として渡る構造的強制が残るため、
  検査抑制だけでは挙動が変わらない（二重強制）。切り出しには言語再設計が要る — 別 RFC
- **fmt のアブレーション** — ベンチループに fmt が存在しないため測定不能
- 言語横断比較（0019 で完結）・多ラウンド修復・新条件の発明
