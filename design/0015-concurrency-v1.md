# 0015 — タスク境界 v1: 純粋な子・即時完走（採択版）

- 日付: 2026-08-08
- 状態: **採択（4モデル並列レビュー後の全面改稿）**
- 手法: 8体制約棚卸し（T1〜T7）→ 事前登録 → codex / agy / opencode / cursor(grok-4.6-xhigh)
  の攻撃（grok CLI は 4.6 化の無応答で欠席・視点は cursor が代表）→ 統合。
  **草案の中核 P2「遅延実行・await 時完走」は 4/4 棄却**: 「同期サンク」（agy）・
  「スコープ付き遅延呼び出しであり並行性ではない」（codex）・「`.await` が await ではない」
  （cursor）・「`?` 早期脱出時に未開始子が完走してから伝播＝フェイルファスト破壊」（agy Q5）。
  採択版は cursor 代案 E（即時完走）に**純粋子の契約**を重ねて全急所を同時に消す。
  **本 RFC は並行性を名乗らない** — 出荷するのはタスクの型・構造・効果ゲート・診断である

## 1. spawn 構文（4/4 条件付き採択の条件を全部呑む）

- 合法形は **`spawn Path(名前付き引数)` のみ**。Path は静的に一意解決される fn
  （0010 の解決規則そのまま: 自モジュールは裸名・他モジュールは完全修飾）。
  メソッド形・計算された callee・関数値・部分適用に見える形は専用診断で拒否
- **引数は spawn 地点で通常の評価順に一度だけ評価**され、評価済みの値が子に渡る
  （遅延されるものは v1 には存在しない — §3）
- `spawn` は `scope { ... }` ブロック内でのみ合法。Scope は値ではない（第一級 Scope 不在
  — 0014 の捕獲問題を構文で根絶）。ネスト可・Join の所有は生成 scope に固定

## 2. 子の契約 — 能力はタスク境界を越えない（v1 の核心）

- callee は **`uses {}`（能力効果ゼロ）** かつ**全引数型が CaptureSafe** でなければならない
  （既存の検査機構を再利用）。能力・Join・将来の Shared/Task 類は境界を越えられない
- 帰結: **タスクは計画を計算する — 効果は親が await の後で実行する**。クロージャの教義
  （0014）のタスク境界への拡張であり、t6 実測（モデルは「変換=コンビネータ・効果=ループ」
  の分業を事前分布として持つ）とも整合
- codex Q5 の転送意味論問題（同一 `io` の二子渡し）はこの契約で v1 から**構成不能**。
  能力の越境は v2 の Transfer/ShareSafe 規範化（アフィン層）が加算的に緩める

## 3. 実行 — spawn 地点で原子的に完走（cursor 代案 E）

> **[0017 で改訂]** 本節の「spawn 地点で完走」は 0017 で**子は spawn 地点で開始**に変わった
> （実行は並列・結果は spawn 順にコミット）。逐次実行器は差分オラクルとして `--sequential`
> に残る。§3 の「並列化してもバイト列不変」という主張は**実機で反証され**、代わりに
> **XN6011（飛行中の効果禁止）**が飛行中の観測を構成不能にすることで一致を保証する。
> 本節の conformance ケース「子のトラップは spawn 文で報告・spawn と await の間の文が
> 実行されないことを stdout で証明」は XN6011 の**拒否ケースに置換**された
> （記録は `xenith-cli/tests/concurrency.rs`）。詳細は design/0017。


- `spawn f(args)` は**その場で子を完走させる**。`Join<T>` は ready な箱、`.await` は
  移動取り出し。「spawn = 開始」の直観に一致し、`.await` は結果の受領
- **決定性の真の解消（T2）**: 子は純粋なので、v2 が子を並列実行しても**観測可能な
  バイト列は不変**。spec/04 の公開約束は無条件・無注記で維持され、並列化の扉は
  開いたまま — 「順序を契約から除外する」注記すら不要
- DRF-SC の主張は v1 の文面から**全削除**（「空虚に真」を安全性の証拠に引用させない — cursor）
- 早期脱出（`?` / trap）: 完走済みの未消費結果は破棄。子は純粋なので破棄に副作用は
  原理的に伴わない — agy のフェイルファスト破壊が構造的に消滅

## 4. Join<T> — prelude 型ではなくコンパイラ管理の消費ハンドル（codex Q3 採択）

- D1 コピーの対象外・非 CaptureSafe・格納/返却/捕獲/引数渡し不可・`.await` は
  **ちょうど一度**（データフロー検査: 再 await・分岐片側 await 漏れは診断）
- `spawn f(args);` **文形式**はハンドルを作らず scope に登録（値が要らない fire —
  ただし v1 は即時完走なので意味は「呼んで捨てる」。非 Unit 戻り値の文形式は診断）
- 非 Unit の Join を await せず正常脱出 = 診断（結果の黙殺を許さない）。
  子は `Result` を返してよく（純粋な失敗）、`j.await?` で親に伝播

## 5. 名前・効果・クロージャ境界

- 効果 `Task.spawn`（既存の開放効果名前空間 — `uses {Task.spawn}` は今日も不活性で
  コンパイルされ後方互換）。`.await` は効果を持たない（0004 維持）
- `.await` 後置構文を XN1008 から切り出して Join にのみ解禁。async fn / async クロージャ /
  fn 値の禁止は不変
- クロージャ本体では spawn / scope / `.await` すべて禁止（柱1の暗黙 `uses {}` が
  Task.spawn を自動拒否＋専用注記）

## 6. 診断と teaching（0009 規律）

scope 外 spawn / callee の uses 非空（「子は純粋 — 効果は親で」teach）/ 非 CaptureSafe
引数 / メソッド・計算 callee / Join 逸脱（格納・返却・捕獲・引数渡し）/ 二重 await /
未 await 脱出 / 文形式の非 Unit。全て explain 完備・teach は正典文
**「タスクは計画を計算する — 効果は親が await の後で」**に収束・
`--diagnostic-teaching=off` バイト同一・0009 予算

## 7. 工程 — 意味論が先、実装が後（codex Q4 採択）

1. **conformance ケースを意味論と同時に規範化**（正常系: 2子 fan-out・Result 伝播・
   ネスト scope。拒否系: §6 の全診断。実行系: 評価順・破棄規則）— 実装より先にコミット
2. feature gate 内で構文・検査・実行・診断を揃える（gate 中は既存動作バイト不変）
3. 出荷境界で spec/04・spec/03 追記（「純粋子ゆえ順序は観測不能」一文でバイト保証無傷を
   明記）・ガイド追記・gate 解除を**同時に**行う
4. 測定（tier-7: タスク構造の一発正解率・XN 新診断の発火分布 — 罠は想像でなく
   事前サンプリングから）は別 RFC

## 8. 入れないもの

- **遅延実行**（4/4 棄却の記録として明記 — 再提案は「spawn とは別語彙」でのみ）
- 能力のタスク境界越え・Transfer/ShareSafe 規範化・チャネル・Shared/Mutex/atomics・
  キャンセル・並列実行・複数エグゼキュータ（v2+: アフィン層の後）
- **spawn への関数値/クロージャ — 表面凍結**（cursor: 同一キーワードへの意味追加は
  負転移。将来の関数値 spawn は別キーワード・別 RFC。P6 の旧文言
  「0004 全面改訂が恒久解決」は削除）
- タスク内 suspension 点・async 注釈・DRF-SC の言及

## 9. 却下された草案要素（記録）

- **遅延実行・await 時完走** — 並行性ではなく同期サンク。将来の同時性導入が観測破壊に
  なる袋小路。誤ったメンタルモデルの教材（4/4）
- **`Join<T>` を prelude nominal 型に** — D1 コピーで二重 await が型を通る。
  消費ハンドル＋データフロー検査に置換
- **能力を子に渡す例（`spawn worker(io: io, ...)`）** — 転送意味論なしの能力越境は
  v2 の DRF を死なせるチュートリアル固化（codex Q5 / cursor #4）。純粋子契約で根絶
- **「T2 解消」の自称** — 遅延では先送りに過ぎなかった。純粋子＋即時完走で初めて真に解消
- **「並行性 v1」という題名** — 同時性ゼロの出荷物に並行性の語彙を与える誇大表示
