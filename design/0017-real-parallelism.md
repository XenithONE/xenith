# 0017 — 本物の並列性: 飛行中は静かに（採択版）

- 日付: 2026-08-08
- 状態: **採択（4モデル並列レビュー後の全面改稿）**
- 手法: 4案サーベイ＋審査 → 事前登録 → codex / agy / opencode / cursor(grok-4.6-xhigh) の
  攻撃 → 統合。**4/4 却下**。草案の「ゼロ意味論変更・観測不能・spec に一行も足さない」は
  **虚偽**だった。実機で確認: `spawn boom(); io.write("PARENT")?; a.await;` は現在
  **PARENT を印字せずに**トラップする。並列化すれば PARENT が出る。**観測可能な差である**
- 救済は opencode の代案: **子が飛行中は親が効果を起こせない**ようにする。
  出力が起きないなら、トラップのタイミングは観測できない

## 1. 中核規則 — 飛行中の効果禁止（新診断）

- **XN6011 EffectWhileTasksInFlight**: 最初の `spawn` から**すべての Join が消費されるまで**の
  区間で、親は能力操作および `uses` 非空の関数呼び出しを行えない
- 検査は既存の JoinState 機構（生きている Join の追跡）で完結する。データフロー既存
- **teach 文は変えない**: 0015 の正典文
  「a task computes a plan — effects run in the parent, after await」は
  **既にこの規律を述べていた**。新規則はそれを検査で強制するだけである
- 許される形（await 後は効果可）:
  ```xenith,planned
  scope {
      let a = spawn plan(n: 1);
      let b = spawn plan(n: 2);
      let sum = a.await + b.await;   // ここで飛行終了
      io.write(text: sum.to_text())?; // 効果は合法
  }
  ```

### これで何が救われるか

| 観測チャネル | 逐次 (0015) | 並列 (0017) | 一致 |
| --- | --- | --- | --- |
| stdout | 飛行中は空 | 飛行中は空（XN6011 が保証） | ✅ |
| 子のトラップ | spawn 地点で報告 | join 点で報告・**出力差ゼロ** | ✅ |
| 子の発散 | spawn 地点でハング | join 点でハング | ✅ |
| 終了コード | 101 / 1 / 2 | 同一（トラップ選択は §3） | ✅ |
| ピークメモリ・スレッド数・実時間 | 小 | 大 | ❌ **§4 で決定性の対象外と宣言** |

## 2. 正直な改訂の宣言（cursor Q5 への回答）

草案は「spec に一行も足さない」を成功条件にしていた。これは**改訂を改訂と名乗らずに
行う**ことだった。採択版は逆にする:

- **spec/04 を改訂する**: 「子は並列に実行され得る。トラップと発散は join 点で表面化する。
  飛行中の親の効果は XN6011 で拒否されるため、stdout と終了コードは逐次実行と一致する。
  **ピークメモリ・スレッド数・実行時間・ホスト資源枯渇（OOM/スタック溢れ/panic）は
  決定性保証の対象外**である」
- **0015 の conformance を更新する**: 「子のトラップは spawn 文の位置で報告」ケースは
  **XN6011 の拒否ケースに置き換わる**（親の io.write が飛行中にあるため）。
  置き換えは記録として残す。これは劣化ではなく、**観測差を構成不能にした**結果である
- ガイドに1行追加（飛行中の効果は書けない・await の後で）

## 3. 決定性の設計 — 結果は spawn 順にコミット（codex Q5 への回答）

codex の反例: `let a = spawn TrapNow(); let b = spawn Forever();` — 並列で a のトラップを
選んでも、`std::thread::scope` は b を join するまで抜けられず、逐次なら exit 101 の場面で
**ハングする**。XN6011 は出力を止めるだけでこれを救わない。よって:

- **結果は spawn 宣言順にコミットする**。子1の結果を確定 → 正常なら子2へ、という順序。
  これは逐次実行の運命決定順と**同一**である:
  - 子1が発散 → **ハング**（逐次も spawn 地点でハングする — 一致）
  - 子1が正常・子2がトラップ → 子2のトラップを報告（逐次も同じ）
- **協調キャンセル**: あるトラップが確定した時点で、残りの子に停止要求を出す。
  インタプリタは**安全点**（文の境界・ループ反復・呼び出し）で停止フラグを見る。
  発散する兄弟もループ反復で必ず安全点に来るので確実に回収できる。
  これは**言語機能のキャンセルではない**（`P7` のキャンセル API は依然として未出荷）—
  実行器がプログラムの終了を確定させるための内部機構である
- 用語の精密化（codex の指摘）: 「未 await を scope 脱出で join」は**文形式 spawn**
  （Unit 戻り）にのみ適用される。`let` 束縛された Join は 0015 どおり
  **ちょうど一度 await** が必須であり、両者は矛盾しない
- **同時生存数は語彙的に有界**（実測確認済み）: Join はコンテナに格納できず脱出もできないため、
  同時に生きる子の数は**ソース上の未消費 let 束縛の数**で上限が決まる。
  ループ内 spawn は各反復で生成・消費されるので同時1つ（agy のスレッド爆発懸念への回答）。
  それでも**上限は実装が固定のスレッド数で待たせる**（M:N 風のキュー — 無条件 1:1 にしない）
- `Value` の `Send` を型で保証（`Rc` / 内部可変性を持ち込まない — コンパイル時に強制される）

## 4. Arc + COW の要件（Q2 への回答）

- 集約腕を `Arc` 化し、変更は書込み経路に沿って**再帰的に** `Arc::make_mut`
- **必須テスト（opencode の反例）**:
  ```xenith,planned
  let outer = [[0]];
  let inner = outer.get(index: 0);   // D1: 値コピー
  // inner を変更しても outer は不変
  ```
  ネストした集約で外側だけ COW し内側の共有ノードを直接変更する実装は**バグ**である
- 性能の非決定（子が Arc を保持している間の親の変更が深いクローンを誘発）は
  §1 の飛行中規則により**親が変更を書けない区間**に限定されるが、
  §4 の「資源効果は保証外」に含めて明記する

## 5. 主ゲート — 相互一致テスト（cursor Q5 の代案）

「65ケースが通る」は**壊れる軸を測定しない**。主ゲートを差分テストにする:

1. **逐次実行器を残す**（`--sequential` 内部フラグ）。**同一プログラムを両実行器で走らせ、
   stdout・終了コード・診断がバイト一致**することをテストする
2. 相互一致の対象に**新ケース**を追加: 子のトラップ・子の発散（タイムアウト付き）・
   複数子の同時トラップ（spawn 順コミット）・**トラップ＋発散兄弟**（codex の反例 —
   協調キャンセルで exit 101 に到達すること）・**発散する子1＋正常な子2**
   （両実行器ともハングすること — タイムアウトで確認）・ネスト scope・ループ内 spawn・
   飛行中効果の拒否（XN6011）
3. 既存 conformance は「更新された1ケースを除き」全通過
4. ベンチの凍結参照解（24〜28本）がバイト同一に再現

## 6. 実装スライス

1. `Value` の Arc/COW 化 — **逐次のまま**全既存テスト緑（ネスト COW テスト込み）
2. XN6011（飛行中の効果禁止）＋ conformance 更新＋ガイド1行
3. 並列実行器＋**spawn 順コミット＋協調キャンセル（安全点）**＋スレッド上限＋
   相互一致テスト基盤
4. spec/04 改訂（§2 の文言）・0015 の該当節に追記

## 7. 入れないもの

- 所有権/アフィン層（0018 Seam Affinity — **能力の越境**が要るときに初めて必要）
- 効果つき子・チャネル・Shared/Mutex・キャンセル・work-stealing
- 資源枯渇の決定的トラップ化（保証外と宣言するに留める）

## 8. 却下された草案要素（記録）

- **「純粋な子だから並列化は観測不能」** — 純粋性が排除するのは能力経由の副作用だけ。
  **制御効果（トラップ・発散）と資源効果は残る**（4/4）
- **「0015 の契約はバイト単位で不変」** — 実機で反証（PARENT が印字されるようになる）
- **「spec に一行も足さない」** — 改訂を改訂と名乗らない行為（cursor Q5）
- **主ゲート = 65ケース通過** — 壊れる軸を測定しないゲート。相互一致テストに置換
- **無条件 1:1 スレッド対応** — 上限なしは資源枯渇を招く（agy Q5）
- **到着順のトラップ選択** — 発散する兄弟がいると exit 101 に到達できない。
  spawn 順コミット＋協調キャンセルに置換（codex Q5）
