## 1. カーネル表

| 項目 | 決定 | 理由 |
|---|---|---|
| **評価順序** | 厳密な左→右。引数・フィールド初期化子・代入の全て。レシーバは引数より先 | 副作用順序の推測をLLMにさせない。順序が決まっていれば修復が決定的になる |
| **短絡** | `&&` `\|\|` のみ短絡。他は全評価 | 例外を2つに限定して覚えやすくする |
| **束縛** | `let` = 不変、`var` = 可変。可変化に修飾子を付ける形（`let mut`）は採らない | 修飾子は「付け忘れ」が起きる。別キーワードなら書いた時点で確定する |
| **フィールド** | 既定で不変。`var field` で可変。可変化は排他所有の左辺値を要求する | 共有された可変状態を構文レベルで作りにくくする |
| **初期化** | 確定初期化。観測可能な未初期化値は存在しない | 未定義動作の主要な入口を塞ぐ |
| **ムーブ** | 束縛・代入・引数渡し・返却・パターン抽出・クロージャ捕獲は、`Copy` でない値を**ムーブ**する。ムーブ後の使用はハードエラー | 生存期間注釈なしで所有権を得る唯一の規則 |
| **コピー** | 暗黙のコピーは**スカラのみ**（`Bool` `Int` `Float` `Char`）。集約の複製は `.clone()`、参照数増加は `.share()` で**常に明示** | 隠れたヒープ確保をゼロにする。ゲームのフレーム予算に必須 |
| **コピー発生の正確な瞬間** | ① `Copy` 型の右辺値使用 ② 明示的 `.clone()` ③ `Shared.share()`（参照数のみ）。**排他所有者からのフィールド射影はコピーしない** | 「いつ確保が起きるか」がコードを読むだけで判る |
| **破棄** | 決定的。宣言の逆順。`Shared` は参照数が0になった瞬間に破棄。**ファイナライザ無し** | GCポーズを持たない。16msフレームで予測可能 |
| **等価性** | `==` は `Eq` を宣言した型の**構造的**等価。`is` は**同一性**で `Shared` とハンドルにのみ適用可。`Float` は IEEE 準拠 | 値の等価と参照の同一を構文で分離する。JavaScript 型の曖昧さを作らない |
| **同一性** | 値は安定した同一性を**持たない**。`Shared` とリソースのみが持つ | 値意味論を純粋に保つ |
| **算術** | 固定幅。**オーバーフローは決定的にトラップ**。`wrapping_*` `checked_*` `saturating_*` を明示的に用意 | 未定義動作を作らない。既定が安全で、逸脱は署名に現れる |
| **添字** | 境界検査あり。`list.get(index:) -> Option<T>` のみ。**パニックする添字演算子は存在しない** | 「1つのやり方」原則。境界外アクセスが型で見える |
| **制御フロー** | `match` は網羅必須。`?` は `Result` / `Option` のみで、決定的な後始末の後に即時 return | 全域性。null と例外の経路を作らない |
| **文の終端** | **`;` が文を終端する。空白は完全に無意味**（§3 参照） | 転移が最大。LLMが改行を入れ替えても意味が変わらない |
| **ブロックの値** | ブロックは式。値は最後の式。末尾に `;` を置くと `unit` になる（Rust と同一規則） | §3 参照。失敗様式が**大声の型エラー**であり、静かな誤りではない |
| **効果** | 閉じた集合。呼び出し先の効果 ⊆ 呼び出し元の宣言。await/spawn した子の効果も伝播 | 局所検査だけで権能の使用が静的に見える |
| **未定義動作** | **安全な Xenith には存在しない。** データ競合は UB ではなく**拒否**される | 「コンパイルが通った＝十分安全」をLLMにとって真にする |
| **アトミクス** | v1 は逐次一貫のみ。relaxed 順序を表面に出さない | 個人維持者が正しさを保証できる範囲に留める |
| **FFI / unsafe** | 字句的に印を付け、効果に現れる。安全コードから所有権マーカーや並行性マーカーを**偽造できない** | 不健全性を1箇所に封じ込める |

並行性に関する項目（`Transfer` / `ShareSafe`・スコープ木・キャンセル点・happens-before）は
[0004](0004-concurrency.md) で定める。

## 2. レビュアー間で割れた点と裁定

| 項目 | 分かれ方 | 裁定 |
|---|---|---|
| 可変性の綴り | `let mut`（agy・opencode） vs `let` / `var`（grok・codex） | **`let` / `var`**。修飾子は付け忘れが起きるが、別キーワードは書いた瞬間に確定する |
| 同一性演算子 | `===`（agy・grok） vs `is`（codex） vs `identical()`（opencode） | **`is`**。`===` は JavaScript の型強制の含みを持つため、誤った転移を招く |
| オーバーフロー | トラップ（codex） vs `checked_*` 必須（opencode） | **既定トラップ＋明示的な変種**。既定が安全で、逸脱が署名に現れる方を採る |

## 3. 0002 §5 の撤回 — セミコロンを採用する

**0002 §5 の決定（セミコロン無し・改行終端・`return` にオペランド必須）を撤回する。**

### 撤回の理由

第2ラウンドで、**4モデル中3モデルの構文サンプルが自発的にセミコロンを書いた**
（codex・opencode・grok。agy のみ書かなかった）。
求めたのは「LLM執筆に最も資する構文」であって、セミコロンの是非は問うていない。
つまりこれは**モデルの素の出力傾向**であり、0002 §4 で採択した
「構文的同型性 / 負の転移」原則が示す通りに振る舞っている。

さらに、私がセミコロンを避けた理由づけ自体が誤っていた。

| | 失敗様式 | 深刻度 |
|---|---|---|
| Rust の `;` の罠 | `fn f() -> Int { x + 1; }` → **型エラー**「Int が期待されたが unit」 | **大声。自動修正可能** |
| Go の `return\nfoo` | ゼロ値を静かに返す。コンパイルも通りテストも通り得る | **静か。最悪** |

私は「Rustの `;` はLLMが間違える」ことだけを見て、**その失敗が大声であること**を見落としていた。
静かに間違うより、うるさく間違う方が桁違いに良い。とりわけ `suggested_fix` を持つ本言語では、
`;` の付け外しは機械的に修正できる。

### 決定

- `;` が文を終端する。**空白と改行は完全に無意味**になる。
- ブロックは式であり、値は最後の式。末尾に `;` を置くと `unit`（Rust と同一規則）。
- これにより「LLMが行を折り返しただけで意味が変わる」位置が言語から消滅する。
  これは 0002 §5 で私が**達成したかったが、改行終端では達成できていなかった**性質である。
- `return` にオペランドを必須とする規則は**維持**する（`return unit` と書く）。安価で、害が無い。

### 未解決として残す

この撤回は論拠に基づくが、**測定ではない**。
`bench/ai/` が動くようになった時点で、セミコロン有無の2方言を用意して pass@1 を実測し、
本決定を追認するか再度覆す。仮説として登録しておく。

## 4. 最小の例

```xenith
struct Player {
    name: String,
    var score: Int,
}

enum Rank {
    Bronze,
    Silver,
    Gold,
}

fn rank_of(score: Int) -> Rank {
    match score {
        s if s >= 1000 => Rank.Gold,
        s if s >= 100 => Rank.Silver,
        _ => Rank.Bronze,
    }
}

fn award(player: Player, points: Int) -> Result<Player, ScoreError> {
    let total = player.score.checked_add(other: points)
        .to_result(error: ScoreError.Overflow)?;

    var updated = player;          // ムーブ。ここから player は使用不可
    updated.score = total;
    Ok(updated)
}
```

`checked_add` の引数が名前付きなのは、引数2個以上の呼び出しで名前付き引数が必須だから（0002 §8）。
`var updated = player;` の後に `player` を使うとハードエラーになる（ムーブ後の使用）。
